# Architecture and MVP contract

The Go command and localhost viewer use the same `internal/bridge` core. Originals are streamed from selected Takeout ZIP/TAR.GZ parts into a new portable archive; archive member paths are never extracted directly onto the filesystem. Source files remain read-only. SHA-256 identifies source parts and media content. A manifest retains source occurrences, sidecars, dates, album relationships and visible unresolved issues even when identical media share a stored file.

The current 0.2.0 beta adds `compare` and recovery from abrupt process termination to the `inspect`, `plan`, `export`, `verify`, `resume` and read-only `serve` command set. The viewer filters repeated content without dropping occurrences, shows dates and source provenance per occurrence, supports keyboard navigation, and can cancel verification. Beta cross-platform qualification remains pending. Richer media-review workflows and an explicit Immich upload adapter are subsequent work. No automatic network transfer occurs. A transfer report covers the selected parts, not an entire Google account.

Core API: `DefaultLimits() Limits`; `Inspect(context.Context, []string, Limits) (*Plan, error)`; `WritePlan(*Plan, string) error`; `ReadPlan(string) (*Plan, error)`; `Export(context.Context, *Plan, string) (*ExportReport, error)`; `Verify(context.Context, string) (*VerifyReport, error)`; `Compare(context.Context, *Plan, string) (*CompareReport, error)`; `ReadManifest(string) (*Manifest, error)`. Repeating export/resume rehashes existing stored files before skipping them and rejects mismatched files. Export acquires an exclusive native writer lock and owns a plan-bound staging checkpoint. Version-1 plans/manifests reject unknown schema versions. Plans contain local source paths; portable manifests do not.

Filesystem safety uses fresh output ownership, bounded parsing, streamed hashing/copying, generated content paths, exclusive staging and checked final writes. Input symbolic links, archive traversal/duplicate member names and unsafe output roots are rejected. Trusted local path ancestors are required; the tool is not a hostile filesystem-race sandbox. Integrity verification compares bytes against the manifest; it does not authenticate an unsigned manifest. Source comparison requires the original source identities.

Google documents secondary JSON metadata and notes that download time can differ from the original photo timestamp: [Google Photos export help](https://support.google.com/photos/answer/3024190?hl=en-GB). Takeout naming variations outside verified matching rules remain unresolved rather than silently selecting a candidate. Original embedded metadata is preserved by preserving original bytes; dates from supported sidecars are recorded separately, not rewritten into media.
